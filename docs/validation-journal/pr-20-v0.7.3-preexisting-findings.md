## False Positives

### __init__.py — 1 CRITICAL (false positive)

#### FP-001: PC-001 — No actual Python code logic to evaluate — CRITICAL

- **What Quorum flagged:** "This is a minimal __init__.py file with only version and __all__ declarations. It contains no actual Python code logic to evaluate against the Python code quality rubric criteria."
- **Why it's a false positive:** A minimal `__init__.py` containing only `__version__` and `__all__` is correct by design. The python-code rubric expects functions and classes; this file is a package metadata declaration, not an implementation file. Wrong rubric applied.
- **Category:** severity-mismatch

### prescreen.py — 4 HIGH (2 false positive, 2 pre-existing)

#### FP-002: PC-014 — subprocess calls use shell=True with variable interpolation — HIGH

- **What Quorum flagged:** Command injection vulnerability in PowerShell execution
- **Why it's a false positive:** The `escaped_path` variable uses `replace("'", "''")` before interpolation into the PowerShell command. The trust model is documented with an inline `# SECURITY:` comment added in this very PR. The tool runs in trusted developer environments, not as a network service.
- **Category:** cli-tool-pattern

#### FP-003: PC-012 — Command injection risk in PowerShell execution — HIGH

- **What Quorum flagged:** User-controlled artifact_path interpolated into PowerShell command
- **Why it's a false positive:** Same as FP-002 — the single-quote escaping and trust model are explicitly documented. CLI developer tool, not a web service.
- **Category:** cli-tool-pattern

## Notes

- **Scope of fixes:** This PR closed 16 accumulated code quality findings: parameterized `check_hardcoded_counts` in prescreen.py (was using hardcoded `range(2, 9)`), narrowed exception handling, added `exc_info=True` logging, extracted pure functions from validate-docs.py to reduce SRP violations, corrected SPEC.md §2.1 (separated 6 shipped critics from 3 planned), and fixed `__version__` from 0.5.3 to 0.7.3.
- **Wrong-rubric CRITICAL:** The `__init__.py` CRITICAL is a rubric applicability issue — the python-code rubric expects implementation code, not package metadata. This pattern suggests a need for rubric selection that accounts for file purpose, not just file extension.
- **CI noise vs. signal:** 35 findings on a PR that was explicitly fixing code quality debt, all pre-existing or false positive. The signal-to-noise ratio demonstrates why the dedicated cleanup was needed — these findings had been creating triage overhead on every PR since #14.
- **Version mismatch fix:** `__version__` was 0.5.3 in `__init__.py` while PyPI showed 0.7.2. A runtime version check by an external consumer flagged the discrepancy.
