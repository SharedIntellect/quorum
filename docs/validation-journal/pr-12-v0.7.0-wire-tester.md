## False Positives

### aggregator.py — 7 findings, all false positive

#### FP-001: PC-002 — tester_result can be None but accessed directly — HIGH

- **What Quorum flagged:** Return values that can be None are not checked before use
- **Why it's a false positive:** The parameter is `tester_result: TesterResult | None = None` and the caller in pipeline.py only passes it when not None. The method itself is called conditionally: `if tester_result: self._apply_tester_results(...)`.
- **Category:** callers-guard

#### FP-002: PC-002 — tester_result attribute access without validation — HIGH

- **What Quorum flagged:** `verification_results` attribute could be missing or malformed
- **Why it's a false positive:** `TesterResult` is a Pydantic model — `verification_results` is a required field validated at construction. If it's malformed, Pydantic raises before the aggregator ever sees it.
- **Category:** internal-interface

#### FP-003: PC-010 — Caught exceptions lack diagnostic context — MEDIUM

- **What Quorum flagged:** Exception handling could fail without sufficient context about which findings were being processed
- **Why it's a false positive:** The logging statements ARE the diagnostic context. Each except block logs the specific error with `%s` formatting.
- **Category:** severity-mismatch

#### FP-004: PC-015 — Docstring contradicts "future version" comment — MEDIUM

- **What Quorum flagged:** Docstring inaccuracy regarding LLM functionality
- **Why it's a false positive:** The docstring says "does NOT call the LLM" (true). A code comment says "a future version could" (aspirational). One describes current behavior, the other acknowledges a possibility. No contradiction.
- **Category:** aspirational-comment

#### FP-005: PC-020 — Broad except Exception in async context — MEDIUM

- **What Quorum flagged:** Overly broad `except Exception` clause without specific error types
- **Why it's a false positive:** `_similarity` and `_deduplicate` are not async methods; `CancelledError` cannot propagate through them. Even if they were, `CancelledError` is `BaseException` in Python 3.9+, not caught by `except Exception`.
- **Category:** broad-except-intentional

#### FP-006: PC-012 — Deduplication without input validation on descriptions — LOW

- **What Quorum flagged:** No input validation on description strings passed to deduplication
- **Why it's a false positive:** `SequenceMatcher` handles arbitrary strings. The descriptions come from LLM-generated findings already validated by Pydantic.
- **Category:** internal-interface

#### FP-007: Security positive observation — INFO

- **What Quorum flagged:** Code demonstrates good security practices (deterministic verdict assignment, structured logging)
- **Disposition:** Informational — not a finding. Acknowledged.

### pipeline.py — 10 findings, all false positive

#### FP-015: PC-003 — Broad except Exception clauses — HIGH

- **What Quorum flagged:** Exception handling uses overly broad clauses that could swallow specific errors
- **Why it's a false positive:** The except blocks protect non-fatal operations (learning memory load, manifest writes) where pipeline resilience takes priority over exception specificity. Each block logs the specific error before continuing.
- **Category:** broad-except-intentional

#### FP-016: PC-004 — _validate_path returns Path or raises ValueError — HIGH

- **What Quorum flagged:** Shared mutable state accessed from multiple threads without synchronization
- **Why it's a false positive:** `_validate_path()` is a pure validation function. Raising `ValueError` on invalid input IS the contract. The return type annotation is correct for the success path.
- **Category:** callers-guard

#### FP-017: PC-012 — target_str from user input without validation — HIGH

#### FP-018: PC-012 — Path traversal in resolve_targets — HIGH

- **What Quorum flagged:** Insufficient validation of glob patterns
- **Why it's a false positive:** `_validate_path()` with boundary checking handles path traversal. The critic flagged the function that contains the validation it's asking for.

#### FP-019: PC-020 — CancelledError swallowed by except Exception — MEDIUM

#### FP-022: PC-006/PC-005 — run_batch_validation same pattern — MEDIUM (×2)

- **What Quorum flagged:** Batch validation function has the same god-function pattern

#### FP-023: PC-007 — Code duplication in manifest updates — MEDIUM
